# auto-video-cut

把「一堆拍好的素材 + 一份文案」自动排成**剪映工程**：画面切分、字幕、配音、时长全自动，
你在剪映里微调后导出。

这是一个**可搬移的只读工具**，不绑定任何路径、不写自己的目录。用法是：

> 在**素材目录**里打开 AI，让它把 `auto-video-cut` 当作制作工具调用。

## 它是什么，不是什么

一句话：**它是"把已有素材按文案排成时间轴"的排版器，不是画面生成器。**

你有素材、有文案，缺的是"每句话配哪段画面、字幕和配音怎么对齐"——这是它的活。
你想要的是"凭空长出画面"或者"给一句话直接出成片"——不是它的活。

### 能接的场景

| 场景 | 为什么适合 |
|---|---|
| 口播 / 讲解 / 教程，镜头是**实拍素材** | 用真实音频时长反推分镜长度，正是它的核心算法 |
| 素材已经拍好，要按文案重排顺序 | 自动轮播池 + 同一素材连续截取，不重复画面 |
| 字幕量大，且必须和配音严格对齐 | 逐句合成，字幕起止时间 = 音频起止时间，不会漂移 |
| 同结构多期批量（换文案不换版式） | 只改 `script.md`，用 `--name` 区分草稿 |
| 需要人最后微调，不接受全自动黑盒 | 产出的是**可编辑工程**，不是成片 |
| 让 AI 代做"写稿 → 排片"，人只做审美决策 | `AGENTS.md` 就是给 AI 的操作手册 |

### 接不了的场景

| 你可能想要 | 为什么不行 | 怎么办 |
|---|---|---|
| **AI 视频直出**（文生视频 / 图生视频：Sora、可灵、即梦等） | **不调用任何视频生成模型**，只把已有素材摆上时间轴 | 先把片段生成好放进工作目录，再当素材引用它 |
| 数字人口播 / 口型同步 | 只放配音轨，没有嘴形对齐 | 用剪映的数字人，或专门的对口型工具 |
| 从素材里听出文案（语音识别） | 文案是**输入**，不是输出 | 先转写成 `script.md` 再进来 |
| 自动看懂画面、按内容挑素材 | 自身没有多模态能力，只读 ffprobe 元数据 | AI 有视觉能力就自己看，否则问用户（`AGENTS.md` §3.3） |
| 转场 / 入场动画 / 花字 / 滤镜 / 蒙版 | 草稿里只写静态的位置和缩放 | 在剪映里手工加；要批量动效得先扩 `jylib.py` |
| BGM / 音乐卡点 | 只放配音轨 | 在剪映里加 |
| 渲染 mp4 / 上传发布 | 只产出工程，不渲染不发布 | 剪映导出；发布这一步永远留给人 |
| 逐帧精剪（多机位、精调色、逐帧对齐） | 时间轴粒度是"分镜"，不是"帧" | 当粗剪用：它排骨架，你在剪映精修 |
| 完全无人化的日更账号 | 它是草稿生成器，不是渲染流水线 | 见下面的说明 |

### 关于"一句话全自动出片"

网上那些"AI 全自主运营账号"（DeepSeek 鲸鱼娘那一批）走的是**另一条路**：画面由模型生成、
用 Remotion 之类的框架整帧渲染成 mp4，全程不需要剪辑软件。那条路的代价是**画面完全模板化**，
而且没有"人再改一刀"的余地。

本工具是**草稿生成器**：产出 `.jybuild/` 和一份剪映工程，你打开剪映还能接着改。
两条路不冲突——渲染出来的 mp4 可以当一个普通素材喂进工作目录，由本工具负责把它和
配音、字幕、其他镜头拼在一起。谁负责"生成"，谁负责"编排"，分工清楚就行。

技术细节和更进一步的方案（素材索引、程序化动画）见 `docs/AI全自动剪辑方案调研.md`。

## 快速开始

### 第 0 步：设一个环境变量

工具**不猜**工作目录，只认 `AVC_PROJECT_DIR`：

```bash
export AVC_PROJECT_DIR=/e/project-video/生物辞典5          # Git Bash
$env:AVC_PROJECT_DIR = 'E:\project-video\生物辞典5'        # PowerShell
```

没设、指向的目录不存在、或者里面没有 `视频/` 子目录，都会直接报错停下。这不是
写在文档里的建议，是代码里的硬检查——同一个 session 里同时看得见草稿目录、素材目录、
工具目录，猜错一次素材就写到别处去了。

生成或回收来的素材（配音、从剪映抽回的朗读、配图）会复制进
`$AVC_PROJECT_DIR/音频/` 和 `$AVC_PROJECT_DIR/图片/`，草稿只引用这些副本，
不会引用剪映的 `textReading/` 缓存或工具自己的 `tmp/`。

另外三个是**可选**的，写了优先、不写自动探测：

| 变量 | 指向 | 不写时 |
|---|---|---|
| `AVC_JIANYING_DIR` | 含 `videoeditor.dll` 的那一层（如 `...\Apps\11.6.0.14552`） | 扫 `%LOCALAPPDATA%\JianyingPro\Apps\`，按版本号锚定 |
| `AVC_DRAFT_ROOT` | 草稿根目录 | `JIANYING_DRAFT_ROOT`（旧名）→ `config.json` → 默认位置 |
| `AVC_FFMPEG_DIR` | 含 `ffmpeg.exe` 的目录 | 走 `PATH` |

写了但指错（目录里没有 `videoeditor.dll`、没有 `ffmpeg.exe`）会直接报错，
不会静默退回自动探测——写错变量却跑出个“看起来正常”的结果最坑。

java 不需要：剪映是 C++/Electron，本工具用 ctypes 直接调它的 DLL，外部依赖只有
ffmpeg、ffprobe 和剪映本身。

```bash
# 1. 在放素材的目录里，看一眼素材清单
python ../auto-video-cut/scan.py .

# 1.5 让 AI 或你自己给每段素材补一句"拍了什么"（填完就能写分镜了）
python ../auto-video-cut/scan.py . --describe

# 2. 写 script.md（格式见下），然后试运行
python ../auto-video-cut/build.py . --dry-run

# 3. 完全退出剪映，正式生成
python ../auto-video-cut/build.py .

# 4. 结构自检
python ../auto-video-cut/validate.py .
```

`--describe` 会输出一份带编号、带"可容纳多少字"的填空清单。这是整条链路里
唯一需要人参与的地方——AI 读不了你的画面，让它自己猜不如让你一句话说清。

## 工作目录长什么样

```
你的素材目录/
├─ script.md          ← 你写（或 AI 写）
├─ 片段1.mp4           ← 素材，随便放，支持子目录
├─ images/封面.png
└─ .jybuild/          ← 工具生成的缓存，可整个删掉
    ├─ normalized/    转码缓存
    ├─ tts/           配音 + 词级时间戳（.wav / .words.json）
    ├─ 剪映配音/        从剪映草稿抽出来的朗读音频（见下「用剪映的音色」）
    ├─ 字幕时间轴.json 每条字幕和每个字的绝对时间（毫秒）
    └─ 分镜表.md       这次生成了什么，给人看
```

## script.md

```markdown
---
标题: 第四期_开场
尺寸: 1920x1080
配音: edge
音色: zh-CN-XiaoyiNeural
语速: -10%
留白: 0.25
---

# 1
文案：这句话是口播，也会成为字幕。
素材：片段1.mp4
起点：2

# 2
文案：换一段素材。写两句也行，会自动切成两条字幕。
素材：片段2.mp4

# 3
文案：这一屏放图，自动加缓慢推拉。
图片：images/封面.png
```

分镜字段：`文案` `素材` `图片` `起点` `时长` `不字幕` `字号` `位置Y`。
全局配置项和写作规范见 `AGENTS.md` 第 4 节（那里写得更细，AI 和人看的都是同一套规则）。

## 配音

`配音: edge` 时用 edge-tts **逐句合成**，每句的真实音频时长决定字幕和画面时长，
所以字幕边界与语音边界严格重合，不会漂移。

常用音色：`zh-CN-XiaoyiNeural`（晓伊，少女音）、`zh-CN-XiaoxiaoNeural`（晓晓）、
`zh-CN-YunxiNeural`（云希，男声）、`zh-CN-YunjianNeural`（云健，解说腔）、
`zh-CN-YunyangNeural`（云扬，播报腔）。完整清单跑 `python ../auto-video-cut/voices.py`
（默认列出**全部中文音色 14 个**：8 个普通话含东北/陕西方言，加港澳台 6 个）。

`配音: 剪映` 是另一条路：**旁白交给剪映的文本朗读**。剪映有几百个音色（情感音、方言、
IP 音色），edge-tts 只有 14 个中文音色，很多时候剪映的更好听。代价是多跑一轮。

### 用剪映的音色（两轮）

```bash
# 第一轮：按字数估算排一版，还没有配音
python ../auto-video-cut/build.py .
```

在剪映里打开草稿 → 选中字幕轨 → 文本朗读 → 选音色生成 → **保存并完全退出剪映**。

```bash
# 第二轮：按真实配音时长重排
python ../auto-video-cut/build.py .
```

第二轮会先把草稿里的朗读音频（`textReading/*.wav`）连同真实时长收进
`.jybuild/剪映配音/`，然后才覆盖草稿。**这个顺序是有意的**——不先救出来，覆盖一次
你就得重新朗读一遍。

收出来之后它就是个普通 wav 了，好处有三个：

- 脱离草稿独立存在。草稿被覆盖、被删掉，音频都还在
- 不依赖剪映版本。升级改了接口，已经固化的音频照用
- 可以跨期复用。固定开场白、片尾口播做一次就够

输出会告诉你命中情况：

```
剪映配音: 从草稿「第四期」收回 22 条朗读音频（新复制 22）
总时长 96.40 秒 / 8 分镜 / 22 字幕 / 1920x1080@30fps / 配音=剪映配音 22/22 条
```

`22/22` 就是全对齐了。分子比分母小，说明那几条是新写的或者还没朗读，已按字数估算——
**只补朗读缺的那几条**，关掉剪映再跑一次即可。

两个注意：**朗读前别改文本**（工具按字幕原文匹配音频，改一个字就失配）；
**这条路线没有词级时间戳**，逐字高亮和 SRT 导出做不了，要那两个就用 `配音: edge`。

只想抽音频、不生成草稿：

```bash
python ../auto-video-cut/cuttts.py 第四期 .        # 抽
python ../auto-video-cut/cuttts.py --list .        # 看库里有什么
```

### 词级时间戳

合成配音时顺手把每个词的边界也存下来了（`.jybuild/tts/*.words.json`），
再汇总成 `.jybuild/字幕时间轴.json`——每条字幕、每个字的**绝对毫秒时间**。

它和音频是同一趟请求出来的，不是事后对齐，所以天然同源。用途：

- 做逐字高亮 / 卡拉OK 字幕
- 导出 SRT（时间直接用，不用自己算）
- 排查"这句到底念了多久"

精度在几十毫秒级（裁剪前导静音会带来最多 40ms 的误差），做字幕看不出。

旧缓存没有这份文件，`build.py` 会提示 `词级时间 3/4 条`。加 `--no-cache` 重跑一次即可补齐。

## 依赖

| 依赖 | 情况 |
|---|---|
| Python ≥ 3.8 | 用运行脚本的那个解释器，不要求它在系统 PATH 里 |
| **ffmpeg / ffprobe** | 需要已安装并在 PATH 里 |
| **edge-tts** | 绿色安装在 `.vendor/`（不入库），删掉即回退「剪映朗读」模式 |

不写系统 Python、不改注册表、不装服务。

从仓库克隆后重建配音依赖：

```bash
python install.py
```

脚本用**当前解释器**（`sys.executable`）的 pip 装进 `.vendor/`，只碰这个目录。
常用参数：

| 参数 | 作用 |
|---|---|
| `--check` | 只检查，不安装（退出码 0=已就绪） |
| `--force` | 删掉 `.vendor` 整份重装 |
| `--index-url tuna` | 换国内镜像，也认 `aliyun`/`ustc` 或完整 URL |
| `--pip-arg X` | 额外透传给 pip，可重复 |

装完用 `python doctor.py` 确认。换机器/换 Python 版本必须重装一次——
`.vendor` 里是平台绑定的编译扩展（`cp313-win_amd64.pyd`），不能跨版本复制。
`install.py` 会把当时用的解释器记在 `.vendor/.interpreter`，发现不一致自动重装。

## 作为 git 仓库

适合。纯文本部分只有 **138KB**，`git add` 之后仓库约 **43KB / 22 个文件**。

| 内容 | 大小 | 入库 | 理由 |
|---|---|---|---|
| 代码 + 文档 + `assets/` 字段模板 | 138KB | 是 | 纯文本，`assets/` 是运行必需的剪映字段结构 |
| `.vendor/`（edge-tts 等 9 个包） | 4.5MB | **否** | 含 9 个 `cp313-win_amd64.pyd`，平台+Python 版本绑定 |
| `config.json` | 千字节 | **否** | 本机剪映路径、字体路径，每台机器不同 |
| `.jybuild/` | 与素材等大 | **否** | 转码和配音缓存，随时可重建 |

`.gitignore` 已经配好。克隆后只差一步：

```bash
python install.py
```

没装也能跑：`doctor.py` 会报 WARN（不是错误），配音自动回退到「剪映朗读」模式，
按字数估算时长、音频留空。你在剪映里点一次「文本朗读」、关掉剪映再跑一次，
就能按真实配音时长重排（见上面「用剪映的音色」）。这条路径已实测通过。

## 关键设计

**为什么能直接读写剪映草稿**：剪映 11 把 `draft_content.json` 加密了（base64 外壳 +
无压缩密文），但 `videoeditor.dll` 里留着 `EncryptUtils` 的加解密导出函数，
`jycrypto.py` 用 ctypes 直接调它——不逆向密钥、不编译 C++、不落临时文件。
草稿索引 `root_meta_info.json` 一直是明文。

**为什么写回要写两个地方**：编辑器加载的是
`Timelines/<main_timeline_id>/draft_content.json`，顶层那份只是镜像。
只改顶层，剪映打开时会用时间轴那份覆盖回去，表现成「改动被回滚」。
所以 `jycore.write()` 会把顶层和时间轴两份连同各自的 `.bak`、`template-2.tmp` 一起写。

**为什么新增片段照抄剪映写过的结构**：剪映自己的校验比文档严。`jyedit` 不手拼字段，
结构来自两处，按先后：①草稿里已有的同类片段（优先，这样会沿用你调好的字体和描边）；
②`assets/jy_template.json`，从 11.6 真实草稿固化的模板。
第二处是为了应付「你刚粗剪完，草稿里只有视频轨」——那时候没有字幕片段可抄，
靠第一处会直接卡住。只换 id、路径、时间、文字；片段挂的附属素材（速度、节拍、
声道、动画）整套复制并重新分配 id，保证每个片段独占自己的一份。

**为什么要先转码**：`prep.py` 把所有素材统一成目标画布尺寸和恒定帧率，
草稿里所有片段的缩放恒为 1，不会因为源素材画幅不一致而错位。

**为什么不写自己的目录**：配音和转码缓存全部落在工作目录的 `.jybuild/`，
所以本目录可以整体搬到任何位置、被多个项目同时引用，甚至设成只读。

## 使用上的限制

功能上做不到的事见上面「接不了的场景」，这里只列**用起来会绊脚**的：

- 写入前**必须完全退出剪映**（含托盘 `JianyingProTray.exe`），否则写进去的内容会被它
  退出时覆盖。`jycore.write()` 会先检查进程，开着就拒绝写。
- **版本锚死在 11.6.0.14552**（`jycore.VERSION`）。草稿字段跟着剪映版本走，
  对不上 `doctor.py` 直接 FAIL，并给出 `winget download` 的下载命令。
- 内置模板只覆盖**字幕和配音**。配图要求草稿里至少有一个视频片段（粗剪完必然满足）；
  一条都没有说明你还没放素材，这时加图也没有意义。
- 它不判断素材"内容"好坏：只读时长、画幅、有没有音轨，不知道这段拍糊了没有。
